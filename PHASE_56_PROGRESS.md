# Phase 56 Progress — Complete Desktop Engine Integration (Graphics Editor)

Date: 2026-11-26
Baseline: local snapshot (Phase 56 is staged locally, not yet pushed; the owner pushes in a batch)

Status: **Implemented and verified locally.** Phase 56 connects the TypeScript graphics engine built across Phases 44–53 to the generated C# desktop editor (PixelForge, from `server/imageEditor/imageProjectGenerator.ts`): the generated app now runs on a genuine C# port of the engine's core and exposes layers with blend modes and masks, selections, the Phase 46 brush, the full Phase 47 filter registry, Phase 48 text/shape content layers, and Phase 52 non-destructive editing (effect stacks, adjustment layers, bake). Every change went through the generator — no generated output was hand-edited. **The generated GUI was compile-verified only and was never run** — this VM has no display and WinForms does not execute on Linux .NET 8; runtime/GUI verification is Phase 57's brief, and nothing in this phase claims the app was launched, clicked, or visually checked. Acceptance is the owner's decision.

## What was built

All work is in `server/imageEditor/imageProjectGenerator.ts` (rewritten/extended) plus one migrated test needle in `tests/phase19_image_editing_engine.test.ts` and the new suite `tests/phase56_desktop_engine_integration.test.ts`. The generator now emits eight app sources; two are new, three are rewritten around the new core, and `Program.cs`/`Workspace.cs` carry over unchanged in content.

- **`PixelEngine.cs` (new, ~75 KB generated)** — a single raw-pixel core for the app. `PixelImage` holds RGBA bytes in the TS engine's row-major layout; `System.Drawing` bitmaps exist only at the display/import/export boundary (`LockBits` with the BGRA↔RGBA swap). Everything else — compositor, filters, brush, tools — works on `PixelImage`, so there is exactly one implementation of each behavior:
  - `Px` mirrors the JS numeric semantics the TS engine relies on (`Math.round` = `floor(v + 0.5)`, not banker's rounding; Rec.601 luminance).
  - `BlendModes` implements the W3C blend + composite formulas from Phase 44 (`BlendChannel` for multiply/screen/overlay/darken/lighten, the full `co = (αs(1−αb)Cs + αs·αb·B + (1−αs)αb·Cb) / αo` composite) and `BlendPaint`, the shared paint path that enforces the Phase 44 alpha lock.
  - `Filters` carries all 16 Phase 47 filters. The descriptor table is **generated from the TS registry at generation time** (`listFilters()`), so ids, names and every parameter's min/max/default cannot drift from the engine. `ResolveParams` reproduces the registry's strict validation (unknown ids/parameters and out-of-range values rejected with named errors; nothing silently clamped). Implementations port the TS kernels: separable box/Gaussian blur (float intermediate, normalized kernel), sharpen, seeded noise (mulberry32 ported with `uint` arithmetic — seed-identical to TS), Sobel edge detect, emboss, wave and swirl distortions (inverse-mapped bilinear, Phase 45 convention, trig snapped at 90° multiples), and the color filters including the Phase 19 brightness/contrast factor `259·(c+255)/(255·(259−c))`. Application is scoped by the app's rectangular selection (filtered inside, original outside — the TS rect-selection rule).
  - `BrushEngine` ports the Phase 46 model exactly: coverage-map strokes (stamps walked at `spacing × size`, build-up `cov += deposit × (1 − cov)` in double precision before the float32 store, applied once at `opacity` through `BlendPaint` so the alpha lock holds), the round hardness profile, EMA smoothing (`k = 1 − amount·0.9`), pressure as input data (absent pressure = full, the TS rule), `PaintStroke`/`EraseStroke` (alpha scaled by `1 − coverage` — a true alpha erase) and `PaintMaskStroke` (the Phase 44 mask-painting port). Settings defaults and the five built-in presets are **emitted from the TS model** (`DEFAULT_BRUSH_SETTINGS`, `BUILT_IN_BRUSH_PRESETS`).
  - `Tools` (fill rect, ellipse, line, bitmap text) and `ContentRender` port Phase 48: the glyph tables for both built-in fonts are **emitted from `glyphRowsFor`** (49 characters each, keyed by char code, plus the fallback glyph), text renders at `max(1, round(fontSize/7))` scale with alignment, outline (dilated coverage minus coverage) and shadow (translated, box-blurred coverage); shapes (rectangle/ellipse/line/polygon/Bézier path) fill through centre-sampled even-odd rasterization and stroke through flattened polylines (16-step cubic flattening, the real cubic formula).
  - `EffectStack.Apply` and `Compositor.Render` port Phase 52/44 compositing: per-layer effect stacks rendered from pristine pixels, adjustment layers filtering the accumulated backdrop cross-faded by opacity × mask, masks, clipping (a clipped layer contributes through the alpha map of the nearest non-clipped layer below; with no base it contributes nothing), blend modes and visibility.
- **`ImageDocument.cs` (rewritten)** — the document model on the raw-pixel core: `EditorLayer` holds `PixelImage` pixels as the source of truth (the `Bitmap` is a cached view) plus all Phase 44–52 state (blend mode, alpha lock, clipped, mask, effect stack, kind, text/shape data). Mask operations (create/invert/apply/remove) mirror the TS rules including the adjustment-layer refusals; `BakeEffects` is the explicit destructive commit and refuses adjustment and content layers with the TS error messages. Content layers store their data and re-render from it (`RenderContentLayer`), so text and shapes stay genuinely editable. **Save/load**: the per-layer manifest gains `BlendMode`, `AlphaLock`, `Clipped`, `Kind`, `File`, `MaskFile` (mask persisted as a PNG carrying the gray value in RGB), `Effects`, `Text` and `Shape`. Phase 19-format folders still load — every new field is read through tolerant `TryGetProperty` helpers with the TS defaults — and stored effects are validated on load through `Filters.ResolveParams`/`DescriptorFor`, so a corrupt stack rejects the file exactly as the TS loader rejects it. `MainForm`'s open path loads into a temporary document and swaps only on success, so a rejected file no longer destroys the open document.
- **`EditorCanvas.cs` (rewritten)** — the surface paints through the engine: brush/eraser strokes are re-rendered from the full point list over a stroke-start snapshot on every mouse move (so spacing/flow/smoothing apply to the whole stroke, as in TS); mask painting routes through `PaintMaskStroke` with the foreground colour's luminance as the gray value; adjustment layers refuse painting (no `StrokeStarted`, no paint); the Select tool maintains the rectangular selection (drawn as a dashed overlay) that scopes filters and paint; the Text tool raises `TextToolClicked` so the shell opens the text-layer dialog at the click point. Zoom/pan behavior and the Phase 54 surface (`ZoomBy`, `BackColor2`) are preserved.
- **`Dialogs.cs` (new)** — `FilterParamsDialog` builds its fields from the filter's descriptor spec (min/max/default/decimals from the registry data); `EffectsDialog` edits a deep-copied effect list (add from the registry, enable/disable, parameters via `FilterParamsDialog`, remove, reorder) and the shell commits only on OK; `TextLayerDialog` and `ShapeLayerDialog` edit the full Phase 48 data (polygon points and Bézier segments are parsed from text with `FormatException` messages shown, never swallowed).
- **`MainForm.cs` (rewritten shell)** — keeps every Phase 54 behavior (panels docked from `WorkspaceData.DefaultLayout`, `KeyPreview`, `ShortcutResolver` dispatch, menus displaying their chords, Swap colors, snapshot undo, JPEG export) and adds the Phase 56 surface:
  - **Layer panel**: opacity (0–100%), blend-mode combo fed by `BlendModes.All`, Visible/Alpha lock/Clipped checkboxes, mask buttons (Add/Invert/Apply/Remove) plus a Paint-mask toggle, an Effects… button, an Add-adjustment-layer button, and a status line (kind · mask · effect count). A `_syncing` guard prevents event feedback; the layer list shows kind/mask/effects/hidden markers.
  - **Filters menu**: built at runtime from `Filters.Descriptors` — every registry filter, parameters via `FilterParamsDialog`, applied through `Filters.Apply` scoped by the canvas selection; on an adjustment layer it directs the user to the Effects dialog instead of pretending to paint.
  - **Layer menu**: add layer / text layer / shape layer / adjustment layer, Edit content… (re-opens the data dialog for text/shape layers), Bake effects, move up/down, delete.
  - **Brush options bar**: preset picker fed by `BrushEngine.Presets` plus Size/Hardness/Opacity/Flow controls writing straight into the canvas's `BrushSettings` model.
  - **Select menu**: Select all / Clear selection.

## Test-needle migration (Phase 19)

`tests/phase19_image_editing_engine.test.ts` test 7.1 asserted `/CompositingMode\.SourceCopy/` on the generated canvas ("true alpha erase") — that was the old canvas's System.Drawing erase mechanism. The Phase 56 canvas erases through the ported engine (`BrushEngine.EraseStroke`, alpha scaled by `1 − coverage`), which is the same true-alpha-erase semantics on the raw-pixel core, so the needle was migrated to `/BrushEngine\.EraseStroke/` with an explanatory comment, following the Phase 37 needle-update precedent. Every other Phase 19 and Phase 54 generated-source needle was checked against the new output and still matches unchanged (including `public Bitmap Flatten()`, `SaveProject`/`LoadProject`, `OnMouseWheel`, `EditorTool.Eraser`, `ZoomBy(float)`, `BackColor2`, `RemoveLayer(int)`/`MoveLayer(int, int)`, and all of Phase 54's Workspace/MainForm needles).

## Limitations (deliberate, not hidden)

- **The generated GUI was never run** — compile-verified only (no display on this VM; WinForms does not execute on Linux .NET 8). Runtime behavior, rendering correctness on screen, and workflow testing are Phase 57's brief.
- **Layer groups are not in the generated app.** Phase 44 groups exist in the TS engine only; the app's layer model and panel are flat. Group support was left out rather than half-wired.
- **Custom raster brush tips are not carried.** The Speckle Tip preset is emitted with its scalar settings only; its 4×4 tip bitmap is not reproduced, so that preset paints with the round profile in the app.
- **Selections are rectangle-only in the app** (the Phase 19 selection model): the TS engine's raster selections (wand, lasso, polygon, feather) are not in the app, and filter/paint scoping is the rectangle's hard in/out rule.
- **Brush pressure is modelled, not sensed**: the mouse reports no pressure, so strokes run at full pressure (the TS rule for absent pressure data). Smoothing is in the model and set by presets; the options bar exposes size/hardness/opacity/flow only.
- **Undo remains the Phase 19 flattened-snapshot mechanism** (a snapshot restores into the active layer's pixels); blend/mask/effect-stack changes are not individually undoable steps.
- **Not exposed in the generated app**: PSD import/export (Phase 49), the 16-bit/grayscale working representations and ICC carriage (Phase 50), the acceleration providers (Phase 51), actions and batch processing (Phase 53), and guides/grid rendering or snapping (the Phase 54 workspace data is carried in `Workspace.cs` as before, and filters are exposed through the Filters menu rather than the layout's filters panel, which still renders no controls — as do history/properties).
- Adjustment layers' blend mode, clipped flag and alpha lock have no effect, mirroring the TS engine's Phase 52 semantics; content-layer effect stacks apply to the render cache and cannot be baked, mirroring the TS refusal.
