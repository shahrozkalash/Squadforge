# Phase 52 Progress — Non-Destructive Editing System (Graphics Editor)

Date: 2026-11-26
Baseline: local snapshot after Phase 51 (staged locally, **not pushed** — batched push is the owner's)
Status: **Implemented and verified locally.** Extends the Phase 19/44–51 image engine in place (`server/imageEditor/`); all non-destructive state lives on the existing `Layer` model — there is no parallel project type. Acceptance is the owner's decision.

## What was built

- **Effect stacks (`Layer.effects: LayerEffect[]`)** — each entry is `{ filterId, params, enabled }` referencing the Phase 47 registry. Parameters are stored **resolved** (schema defaults filled by `resolveFilterParams`) at add/edit time, so what is stored is exactly what renders and what serializes. API: `addLayerEffect`, `getLayerEffects` (defensive copies), `setLayerEffectParams` (wholesale replace, re-validated), `setLayerEffectEnabled`, `moveLayerEffect`, `removeLayerEffect`, and the pure `applyLayerEffectStack(img, effects)` (enabled effects in stack order; input never mutated; returns the input itself when nothing is enabled). Unknown filter ids, unknown parameter names and out-of-range values throw at add/edit time — nothing invalid is ever stored.
- **Render path** — compositing no longer reads `layer.image` directly. A per-render view cache (`computeLayerView`) computes each layer's view once per `composite()`/`compositeRows()` call: pristine pixels → enabled effects in stack order → raster placement warp (image and mask warped by the same matrix, so they stay aligned). Stored pixels are never modified by rendering; the cache is discarded after the render. Content layers (Phase 48) get their effects applied to the render cache the same way. The Phase 51 banded seams keep their identity guarantee: per-layer views are computed from whole layer images before per-pixel blending, so banded and full renders agree byte-for-byte.
- **Adjustment layers (`Layer.kind: 'adjustment'`)** — `addAdjustmentLayer()` creates a layer whose image stays an empty canvas-sized buffer. At composite time it applies its enabled stack to the **accumulated backdrop of its own compositing level** — the canvas at root level, the group's isolated buffer inside a group (Phase 44 groups always isolate in this engine, so the scoping follows the isolation; this is the group-scoping answer, and it is tested). The filtered result is cross-faded back per pixel by `layer.opacity × (mask ? mask/255 : 1)`, so opacity and a Phase 44 mask genuinely modulate the effect (a 0.5-opacity invert of (100,150,200) lands exactly on (128,128,128)). Hidden or opacity-0 adjustment layers are skipped entirely. An adjustment layer does not become a clipping base (it has no alpha footprint), and its own `blendMode`/`clipped` flags have no effect — documented, not faked. Because a neighborhood filter on an adjustment layer needs the whole backdrop, `compositeRows` renders the full composite and slices the requested rows whenever a visible adjustment layer with an enabled effect exists (`hasActiveAdjustmentLayer`); band identity with the full composite is preserved and pinned by test 52.13. Pixel-writing entry points refuse adjustment layers with a named error (`requirePaintableLayer`): `brushStroke`, `eraserStroke`, `paintBrushStroke`, `eraseBrushStroke`, `fillRect`, `drawEllipse`, `drawLine`, `drawText`, the Phase 19 adjustments, destructive `applyFilter`, and `applyLayerMask` (an adjustment layer's mask modulates its effect and cannot be baked). Mask creation/painting stays allowed — the mask is the modulation control.
- **Raster placement (`Layer.placement: number[] | null`)** — the Phase 48 content-placement idea, for raster layers: a Phase 45 transform stored as a row-major 3×3 matrix (the same storage form as `contentTransform`, because transform composition is not closed-form in `Transform2D`). `setLayerPlacement(project, layerId, Transform2D | null)` / `getLayerPlacement` (copy). While a raster layer has a placement, the Phase 45 transform family composes into it instead of baking: `transformLayer`, `rotateLayerFree`, `perspectiveLayer` and `transformGroup` multiply the new matrix into the placement and leave pristine pixels and the stored mask untouched (the mask warps with the placement at render). Without a placement those functions behave exactly as before (Phases 45/48 suites stay green). Clearing the placement restores the byte-exact original render. Placement is raster-only: content layers keep `setContentTransform`, adjustment layers have no pixels — both are refused with named errors.
- **Destructive commit (`bakeLayerEffects`)** — explicitly destructive, named as such: writes a raster layer's stacked result into its pixels and clears the stack; rendering is byte-identical afterwards and a placement (if any) stays in force on top. It throws for adjustment layers (no pixels of their own) and for content layers (their pixels are a render cache of editable data; a bake would be silently overwritten by the next re-render).
- **Persistence (format stays v2)** — `SerializedLayer` gains optional `effects` and `placement`. Serialization writes resolved params and matrix copies. Deserialization validates through the same Phase 47 registry: unknown filter id, unknown parameter, out-of-range value, non-array stack, non-boolean `enabled`, a placement that is not 9 finite numbers, a placement on a non-raster layer, or text/shape data / a content transform on an adjustment layer are all **rejected on load**. Files without the new fields (pre-Phase-52 v2, and v1) load with empty stacks and no placement. `HistoryStack` needed no changes — it snapshots through serialize/deserialize, so undo/redo carries stacks, adjustment layers and placements (test 52.24 undoes adding an effect). PSD import constructs plain raster layers (`effects: []`, `placement: null`); PSD export is unchanged — its merged composite comes from `composite()`, so it includes Phase 52 rendering, while per-layer records carry pristine pixels (see Limitations).

## Limitations (stated honestly)

- **Adjustment layers are level-scoped, not document-scoped.** Inside a group, an adjustment layer filters the group's isolated buffer only — a direct consequence of Phase 44's always-isolate group model. At root level it filters everything below it, which is the classic semantics.
- **An adjustment layer's `blendMode`, `clipped` flag and alpha lock have no effect** — it has no pixels to blend, clip or lock. Its live controls are visibility, opacity and its mask.
- **Effects on content layers apply to the render cache**, regenerated from the editable data on every edit — the stack survives edits (it is layer data, not cache), but there is no way to bake a content layer's stack (see `bakeLayerEffects` above).
- **Canvas-wide operations act on pristine pixels beneath a placement**: crop/resize/step-rotate (and paint tools) operate in the layer's own coordinate space; the placement matrix is not rewritten by them. This is the same documented line Phase 48 drew for content layers' render caches.
- **PSD per-layer records carry pristine pixels** (stacks and placements are not written into PSD layer records — the format has no place for them here); the PSD merged composite does include the full Phase 52 rendering because it comes from `composite()`.
- **Performance note**: a project with an active adjustment layer renders its full composite for any `compositeRows` band request (correctness first; the Phase 51 parallel path still applies to adjustment-free projects).
- **The generated C# desktop editor app** (`imageProjectGenerator.ts`, Phase 19) does not yet expose Phase 52 features, and no HTTP route exposes the new API — as with Phases 44–51, this phase covers the TypeScript engine.
