## Requirement-by-requirement

| # | Requirement | Evidence |
| :--- | :--- | :--- |
| 1 | Per-layer effect stacks: ordered Phase 47 filter ids + params + enabled flag, rendered from pristine pixels at composite time | Stack [box-blur, invert] renders byte-identically to applying the same filters destructively in order, and the layer's stored pixels are proven byte-unchanged afterwards (52.1). Disabling the whole stack — or adding effects disabled — returns the byte-exact original composite (52.2). Reordering the non-commuting pair threshold/box-blur matches both destructive orders byte-exactly, and the two orders genuinely differ (52.3). Removing an effect renders as if it was never there; out-of-range stack indices throw (52.4). |
| 2 | Parameter editing re-renders; invalid ids/params rejected through Phase 47 validation | Changing a blur radius 1→3 via `setLayerEffectParams` renders byte-identically to the destructive radius-3 result (52.5). Unknown filter id, unknown parameter name and out-of-range values throw at add time with nothing stored, and a failed edit leaves the previous parameters intact (52.6) — validation is the registry's own `resolveFilterParams`, and stored params are the resolved set. |
| 3 | Adjustment layers: empty pixels, stack applies to the composited result of everything below, respecting stack position, visibility, and groups if practical | An invert adjustment over two layers equals destructively filtering their flattened composite byte-exactly (52.7). Marker pixels on a layer above the adjustment are pixel-exact (52.8). Hiding the layer removes the effect exactly (52.9). Opacity cross-fades backdrop vs filtered result (exact midpoint bytes at 0.5) and a Phase 44 mask modulates per pixel (52.10–52.11). **Group scoping is implemented as level scoping**: inside a group the adjustment filters the group's isolated buffer only — the outside layer is provably untouched (52.12). A spatial (blur) adjustment sees the full backdrop, and row bands stay identical to the full composite (52.13). An empty adjustment layer is inert; painting or transforming one is refused with a named error (52.14). |
| 4 | Non-destructive placement for raster layers (offset/scale/rotation as data, originals recoverable) — honest subset only | `Layer.placement` stores a Phase 45 transform as a 3×3 matrix. An offset placement moves the render while stored pixels stay byte-identical, and clearing it restores the byte-exact original composite (52.15). A 90° rotation placement renders identically to the same transform applied destructively (52.16). While placed, `transformLayer`/`rotateLayerFree`/`perspectiveLayer`/`transformGroup` compose into the placement instead of baking (combined translation pinned exactly) (52.17); the layer mask warps with the placement and stays aligned (52.18); effects apply in the layer's own space before placement (52.19). The subset line: placement exists for raster layers only — content layers keep Phase 48's `contentTransform`, adjustment layers have no pixels; both are refused by `setLayerPlacement` with named errors. Nothing is baked and called non-destructive. |
| 5 | Persistence + history: field-exact round-trip, v2-compatible, older files load, corrupt stacks rejected, undo/redo carries the state | A project carrying a stack (one effect disabled), a placement, an adjustment layer with a stack, and a text layer with a stack round-trips field-exactly (`serialize → deserialize → serialize` deep-equal) and renders pixel-identically (52.21). Pre-Phase-52 v2 files (fields absent) and a v1-shaped file load with empty stacks and no placement (52.22). Six corrupt forms are rejected on load: unknown filter id, out-of-range param, non-array stack, short placement, placement on a text layer, text data on an adjustment layer (52.23). Undo of adding an effect restores the original render and empties the stack; redo reapplies it (52.24, via the existing serialize-based `HistoryStack`, unchanged). |
| 6 | Explicit destructive commit: bake the stack into pixels, clear it, rendering unchanged | `bakeLayerEffects` writes the stacked result into the layer's pixels (byte-equal to the destructive chain), clears the stack, and the composite is byte-identical before and after (52.25). A placement survives a bake and stays in force (52.26). Baking is refused for adjustment layers (no pixels) and content layers (pixels are a render cache) with named reasons (52.27). The operation is documented as destructive in its name, its doc comment and these docs. |

## Known limitations

Adjustment layers are level-scoped (inside a group they filter the group's isolated buffer only — Phase 44 groups always isolate); an adjustment layer's blend mode, clipped flag and alpha lock have no effect (its live controls are visibility, opacity and mask). Effects on content layers apply to their render cache and cannot be baked. Canvas-wide operations (crop/resize/step-rotate, paint tools) act on pristine pixels beneath a placement; the placement matrix is not rewritten by them. PSD layer records carry pristine pixels (stacks/placements are not written to PSD), while the PSD merged composite includes the full rendering. A project with an active adjustment layer renders its full composite for any band request. The generated C# desktop app and the HTTP routes do not yet expose Phase 52 features. Full detail in `PHASE_52_PROGRESS.md`.
