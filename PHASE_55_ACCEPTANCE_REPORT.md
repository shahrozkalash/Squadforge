## Supported platforms (as actually verified)

- **TypeScript engine** (`server/imageEditor/`): platform-independent TypeScript/Node code. **Verified on this Linux x64 VM under Node v24.22.1** — all 356 graphics tests, the typecheck, the benchmark and the batch file I/O ran here. Phase 19's suite is part of the pushed repository and its CI history; **Phases 44–55 are staged locally and have not yet run in CI** (they run when the owner pushes the batch). No other OS/Node combination was exercised in this environment, so none is claimed beyond "any platform Node runs on, verified on Linux/Node 24".
- **Generated desktop app** (PixelForge): a Windows WinForms application (Phase 18 pipeline). **Compile-verified only**, on this Linux host via the .NET SDK 8.0.428 cross-build: restore + build exit 0 and PE-verified artifacts in Phases 19/54/55. It has **never been run on any platform in this environment** (no display, no Windows host), so runtime behavior on Windows is unverified.
- **GPU**: no platform is supported for GPU execution — none exists (see limitations).

## Consolidated known limitations

Gathered from the phase reports; nothing here is new in Phase 55, and nothing is hidden:

- **No GPU execution exists or is claimed** (Phase 51): no GPU hardware in this environment and no WebGPU in Node here; what ships is the provider interface, registry and honest detection (which reports GPU unavailable, asserted by tests) for a future backend to register into.
- **Parallel CPU is slower than serial on this VM** (Phase 51, re-measured in 55): per-call worker spawn under the tsx loader, whole-input structured clones, ~1.5 effective cores. Workers are one-shot (no pool, no band-sliced transfers); only box-blur and gaussian-blur are band-separable — all other filters run serially.
- **No JPEG codec in the TS engine** (Phase 50): JPEG bytes are recognized and refused with the exact reason; the generated C# app (System.Drawing) is the only JPEG path. No ICC application and no gamma linearization anywhere — the documented working assumption is sRGB-encoded values as stored. Layers store 8-bit RGBA only; 16-bit and grayscale are working representations and codec paths. Sub-8-bit and interlaced PNGs are rejected.
- **PSD is scoped, not full Photoshop compatibility** (Phase 49): content layers export as rendered pixels; group blend is written as `norm` (no pass-through in this engine); opacity quantizes to 1/255; image resources are skipped/written empty. **PSD layer records carry pristine pixels** (Phase 52): effect stacks, placements and adjustment-layer effects are not written to PSD — the file's merged composite does carry the full rendering — so a PSD round trip of a project using non-destructive state reproduces the pristine render exactly (proven in 55.2), not the graded one.
- **Adjustment layers are level-scoped**, not document-scoped (Phase 52): inside a group they filter the group's isolated buffer only; their blend mode, clipped flag and alpha lock have no effect. Effects on content layers apply to the render cache and cannot be baked. Canvas-wide operations (crop/resize/step-rotate, paint tools) act on pristine pixels beneath a placement and do not rewrite placement matrices.
- **Groups render as a unit** at their lowest member's stack position (Phase 44): members must stay contiguous; groups have no masks and cannot themselves be clipped; clipping is same-level only.
- **Selections are session-level values** (Phase 45): they persist by conversion to a layer mask. Rotation/perspective keep the canvas size (off-canvas content clips); resampling is bilinear only; `Transform2D` has no shear.
- **Brush pressure is modeled input data, not sensed** (Phase 46): no Pointer Events/device wiring; the EMA stabilizer lags at high smoothing; custom-tip stamps snap to an integer footprint; presets live outside the project file.
- **Filters**: only wave and swirl distortions are implemented and exposed (Phase 47); blur edges replicate; sharpen has no radius control; noise is uniform per-channel; filters ignore the alpha lock (the Phase 19 adjustments' contract).
- **Typography/vectors**: bitmap fonts only (Phase 48) — two built-in typefaces, no system fonts, no anti-aliasing, no text wrapping; one shape per shape layer; canvas crop/resize/step-rotate act on content render caches, not content data.
- **Actions vocabulary is the 14 operations** (Phase 53): painting, selections, masks, groups, transforms, content layers and effect stacks are not recordable steps; layer targeting is by non-unique name (first match); batch concurrency overlaps file I/O only (decode/replay/encode are synchronous) and cancellation takes effect between files; batch inputs are single codec-decoded images (PNG/BMP), not project files or PSDs.
- **Workspace/UI reach**: the generated C# shell renders tools/layers/colors; filters/history/properties exist in the layout data without controls yet (Phase 54). The generated app carries the default workspace as generated code and does not load/save workspace files. Guides/grid are data + snapping logic — no rendering (no overlays, no rulers) and no editor surface calls snapping yet. Visual accessibility is unverified and unclaimed; the tested claim is keyboard-only operation of the 21 documented commands. **The generated GUI has never been run or visually verified on any platform.**
- **Exposure**: the HTTP routes and the generated C# app do not expose most Phase 44–54 features (PSD, actions/batch, the async acceleration API, effect stacks, workspace persistence); the full feature set is reachable today through the TypeScript engine API and its tests.

## Release recommendation

**Yes — the graphics editor, as an engine, is complete against the roadmap (Phase 19 + Phases 44–55), and is recommended for owner acceptance.** Evidence: every roadmap phase is implemented with genuine, exact-value tests (356/356 graphics tests passing in one run, including the 8 cross-phase integration tests added here); `npx tsc --noEmit` is clean; the Phase 51 benchmark re-ran green with every parallel result byte-identical; the generated desktop app recompiled successfully from the current generator. The integration phase found **no engine defects** — the subsystems compose exactly as their individual phases documented, including across serialization, PSD interchange, parallel execution, the 16-bit pipeline and batch processing.

The recommendation is for the **engine**. Three honest caveats accompany it: (1) the generated desktop GUI is compile-verified only and has never been run — accepting the engine is not accepting a visually verified application; (2) GPU acceleration does not exist — the architecture is ready for a backend, the execution is not there; (3) Phases 44–55 are verified locally and are staged, not pushed — CI confirmation comes with the owner's batch push. Final acceptance rests with the owner, as with every phase.
