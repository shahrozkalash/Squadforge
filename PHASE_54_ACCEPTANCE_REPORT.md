## Known limitations

The generated GUI was never run or visually verified (no display on this VM; compile + PE verification only — the Phase 36 `--smoke` mode belongs to the Avalonia app, not this WinForms editor). The generated shell renders three of the six layout panels (tools, layers, colors); filters/history/properties exist in the emitted layout data but have no controls in the Phase 19 shell yet, so their layout entries have no visible effect there. The generated app carries the default layout and shortcut map as generated code; it does not load/save workspace files — persisted custom layouts and rebindings live in the TS engine's `serializeWorkspace` for now. Guides and grid are data plus pure snapping logic: nothing renders guide lines, a grid overlay or rulers in any surface yet, and no editor surface calls the snapping functions. The shortcut map covers the documented 21 commands; adjustments/filters/batch have no bindings. Plain-letter tool shortcuts fire under the form's key preview whenever the main form is focused (the main form has no text-entry fields). Visual accessibility is unverified and unclaimed.
