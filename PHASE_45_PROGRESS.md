## What was built

All in the existing engine — `types.ts` (model) and `imageCore.ts` (operations):

- **Selection model** — `SelectionMask`: a single-channel grayscale raster the size of the canvas (255 = fully selected), the same representation as a Phase 44 `LayerMask`, so selections and masks bridge directly. Shape selections sample pixel centres ((x+0.5, y+0.5)), keeping ellipse/polygon membership symmetric and exactly testable.
- **Shape selections** — `rectSelection` (raster form of the Phase 19 rect), `ellipseSelection` (inscribed-ellipse centre rule), `polygonSelection` and `lassoSelection` (freehand path closed and filled with the same even-odd ray-casting rasterizer; < 3 points rejected).
- **Color selections** — one documented distance for both tools: the maximum absolute per-channel difference across R, G, B and A; a pixel matches when distance ≤ tolerance (inclusive boundary, exact). `magicWandSelection` flood-fills the connected region around the seed (4-connectivity, compared against the seed color), or the whole image with `contiguous: false`. `colorRangeSelection` selects globally against a target color. Seeds out of bounds and tolerances outside integer 0..255 are rejected.
- **Selection operations** (pure — they return new selections and never mutate their input) — `invertSelection` (v → 255−v; empty inverts to full), `featherSelection` (separable box blur, kernel 2·radius+1, edges clamped, computed in float and rounded once — a hard edge at radius 1 takes the exact intermediates 85/170), `expandSelection`/`contractSelection` (separable max/min morphology with a square structuring element; partial values propagate by maximum), plus `selectedPixelCount` and `selectionBounds` (null when empty).
- **Bridges to the Phase 44 model** — `selectionFromLayerAlpha` (per-pixel alpha scaled by the layer's mask when present; layer opacity excluded — it is a blending factor, not footprint) and `applySelectionAsMask` (installs a copy of the selection as the layer's mask, size-checked; the mask then drives compositing, clipping bases and everything else Phase 44 built on masks).
- **Warp core** — one projective warp engine (`warpImage`/`warpChannel`): a 3×3 source→destination matrix, inverted and bilinear-sampled; pixel (x, y) is sampled at the point (x, y) exactly, samples outside the source are transparent/0 with no edge renormalization. Trig is snapped near multiples of 90°, so right-angle warps stay pixel-exact.
- **Free rotation** — `rotateImageFree` (arbitrary angle about the image centre, canvas size unchanged), `rotateSelectionFree`, and `rotateLayerFree`, which rotates a layer's Phase 44 mask with its pixels so they stay aligned. A 90°/180°/270° free rotation reproduces the Phase 19 exact step rotations bit-for-bit (asserted in tests).
- **Perspective transformation** — `solveHomography` (Gaussian elimination on the standard 8×8 system, h33 = 1) with post-solve validation: singular results and solutions that do not map the corners where asked are rejected as degenerate — the linear system alone can "solve" three-collinear-corner configurations into a collapsing matrix, and that is now caught. `perspectiveImage`/`perspectiveSelection`/`perspectiveLayer` move the source corners (0,0), (W−1,0), (W−1,H−1), (0,H−1) to the given TL/TR/BR/BL corners; layer masks warp with their layer.
- **Transform model (handles)** — `Transform2D` (`identityTransform`, `transformMatrix`): scale, then rotate, both about (`centerX`, `centerY`), then translate — the semantics of dragging transform handles. Applied via `applyTransformToImage`, `applyTransformToSelection`, `transformLayer` (pixels + mask), and `transformGroup` (every layer in the group's subtree, nested groups included; layers outside the group untouched). Zero scale and non-finite fields are rejected.

## Limitations (stated honestly)

- **Selections are session-level values**, not stored in the project file (the serialized format stays v2). They persist by becoming a layer mask via `applySelectionAsMask`. The Phase 19 tools still scope by the rectangular `Rect` selection; the raster selection is not wired into every tool's scoping parameter.
- **Free rotation and perspective keep the canvas size** — content rotated/warped off-canvas is clipped; there is no canvas growth to fit a rotated layer.
- **Resampling is bilinear only** (no bicubic/Lanczos), and warp edge weights are not renormalized — the standard, documented choice for this engine (it matches `resizeImage`'s family of behavior).
- **Expand/contract cost** is O(pixels × radius) per pass (direct window scan, no deque optimization) — correct at any radius, slower for very large radii on large canvases.
- **Transform2D has no shear/skew**; the four-corner perspective warp covers non-affine distortion separately. Group transforms apply the same full-canvas warp to each member layer (layers are canvas-sized in this engine, so this is exact).
- **Magic wand** compares candidate pixels against the seed color (not neighbor-to-neighbor) with 4-connectivity, and the max-channel distance (alpha included) is this engine's metric — it is not Photoshop's tolerance metric.
- **The generated C# desktop editor app** (`imageProjectGenerator.ts`, Phase 19) does not yet expose Phase 45 features — as with Phase 44, this phase covers the TypeScript engine.
