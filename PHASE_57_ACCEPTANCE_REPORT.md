## Known limitations

**GUI interaction itself — mouse canvas events, panel rendering, visual layout — remains unverified until the app is run on a Windows machine.** The harness executes the document/engine calls the GUI makes, not the GUI: canvas mouse handling, dialog behavior, panel rendering and the undo/redo interaction (Form-bound) have never executed anywhere. The generated GUI has never been run on any machine. Undo/redo and shortcut resolution are documented runtime skips (S09/S13) for the reasons above, not passes. All Phase 56 app limitations stand unchanged (no layer groups, rectangle-only selections, scalar Speckle Tip, modelled pressure, PSD/16-bit/acceleration/actions/guides not exposed in the app). The raw `Resize` replaces GDI's `HighQualityBilinear` with the TS engine's bilinear sampling — deterministic and pinned, but a generated app's resized output can differ by rounding from the pre-Phase-57 GDI build; project files are unaffected (PNG IO is byte-exact through the new codec, and GDI-written PNGs still load).

## Acceptance

Phase 57 is complete against its brief — the platform limits were established empirically and recorded with their exact errors, the generated app's engine core and document model were separated from their GDI surface in the generator, and the separated core was genuinely executed on this machine across the full editing workflow surface (layers, brush, blends, masks, filters, content layers, effect stacks, adjustment layers, save/load, backward compatibility, geometry) with 136 passing assertions and no engine defects found — and is recommended for owner acceptance, with the standing caveat that the WinForms GUI itself remains compile-verified only and its interaction is unverified until run on Windows.
