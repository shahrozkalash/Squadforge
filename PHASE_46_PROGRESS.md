## What was built

All in the existing engine — `types.ts` (model) and `imageCore.ts` (operations). The advanced brush renders into a coverage map and applies the finished stroke through the **same** `blendPaint` the Phase 19 tools use, so the Phase 44 alpha lock holds identically, and strokes accept the Phase 19 rect selection and the Phase 45 raster selection as scoping options.

- **Brush model** — `BrushSettings` (`createBrushSettings` merges partial overrides over `DEFAULT_BRUSH_SETTINGS` and validates every field; `assertBrushSettings`): `size` (stamp diameter), `hardness` (round-tip edge profile), `spacing` (stamp interval as a fraction of the diameter; > 1 leaves gaps), `opacity`, `flow`, `smoothing`, `tip`, `pressureSize`, `pressureOpacity`.
- **Rendering model** — a stroke accumulates a float coverage map the size of the layer. Stamps are placed every `spacing × size` pixels along the path, with leftover distance carried across segments (the way real brush engines walk a path) and pressure interpolated linearly between path points. Each stamp deposits `shape × flow × pressure` coverage with the build-up rule `cov += deposit × (1 − cov)` — so flow is the per-stamp build-up rate (two 0.5 deposits give exactly 0.75 coverage) and opacity is applied once at the end as the stroke-level cap. That opacity/flow split is the distinction painting applications draw, and the tests pin it numerically.
- **Round tip** — shape is 1 inside the hardness radius, falls linearly to 0 at the rim, and is a hard disc at hardness 1 (the Phase 19 dot rule); `roundBrushTip` rasterizes the same profile into a tip. Pixel distance is measured in the engine's existing index space, consistent with `paintDot`.
- **Pressure** — `StrokePoint.pressure` is input data: present when a device reports it (0..1, clamped), absent → treated as a full 1. The engine never fabricates a hardware reading. `pressureSize` routes it into stamp diameter, `pressureOpacity` into stamp strength; with both off, pressure is ignored. Zero pressure on either route leaves no mark.
- **Smoothing** — `smoothStrokePoints`: an exponential-moving-average stabilizer anchored at the first point (follow factor `1 − 0.9 × amount`; amount 0 returns the input unchanged). Pressure is smoothed with position. In a stroke, `settings.smoothing` applies it to the path before stamping.
- **Custom tips** — `BrushTip` is a grayscale raster (the engine's single-channel representation, shared with masks and selections). `createBrushTip` validates raw bytes; `brushTipFromImage` / `brushTipFromLayer` derive a tip as luminance × alpha. A stamp draws the tip into its integer-aligned square footprint (side = stamp diameter) with bilinear, edge-clamped sampling — the `resizeImage` convention — so a stamp whose diameter equals the tip size reproduces the tip texel-for-texel, and other sizes scale it.
- **Presets** — `BrushPreset` + five built-ins (`Hard Round`, `Soft Round`, `Airbrush`, `Speckle Tip` with a real raster tip, `Pen Pressure Pen` with both pressure routes on). `getBrushPreset` returns a defensive copy. `serializeBrushPreset` / `deserializeBrushPreset` round-trip through JSON (tip bytes as base64, format/version checked, tip length and every setting range validated — corrupt data throws, as elsewhere in this engine).
- **Color sampling** — `sampleColor` (eyedropper over the full `composite()`, so masks, groups and blend modes are all included in what you pick) and `sampleLayerColor` (one layer's own pixels). Radius > 0 averages the (2r+1)² window, clipped at the canvas edges; out-of-bounds points and negative radii are rejected.
- **Advanced eraser** — `eraseBrushStroke` runs the same coverage machinery and scales alpha by (1 − opacity × coverage); like the Phase 19 eraser it is alpha-only, so an alpha lock makes it a no-op.

## Limitations (stated honestly)

- **Pressure is modeled, not sensed.** The engine accepts per-point pressure as input data and routes it faithfully; no browser Pointer Events (or any device API) are wired to it in this phase — there is no hardware pressure reading anywhere in the repo to consume yet. Where a caller has no pressure, strokes behave as full-pressure, by design.
- **Smoothing lags.** The EMA stabilizer damps jitter but trails the input: at high amounts the rendered stroke ends short of the final raw point and cuts sharp corners. That is the standard stabilizer trade-off, stated rather than hidden; rope/brush-follow stabilizers are not implemented.
- **Opacity/flow are the engine's documented model** (flow builds coverage per stamp, opacity caps the stroke once) — a close relative of Photoshop's model, not a claim of identical internals; in particular a stroke is applied to the layer in one pass, so a stroke cannot pick up its own freshly laid color mid-stroke (no smudge-style feedback).
- **Custom-tip stamps snap to an integer footprint** (position and side are rounded), so sub-pixel tip placement is quantized; the round tip keeps the Phase 19 continuous-centre behavior.
- **Presets are library/session data**, stored via their serialized JSON form wherever the caller keeps it; they are not embedded in the project file (format stays v2).
- **The generated C# desktop editor app** (`imageProjectGenerator.ts`, Phase 19) does not yet expose Phase 46 features — as with Phases 44/45, this phase covers the TypeScript engine.
