## Known limitations

No GPU execution, no GPU provider, and no GPU figures — no GPU hardware exists in this environment and Node here exposes no WebGPU; only the architecture (interface, registry, honest detection) ships. The parallel provider is **slower than serial on this VM** at both benchmarked sizes (measured: per-call one-shot worker spawn ≈ 252 ms/worker under the tsx dev loader; whole-input structured clones ≈ 116 ms per 16.7 MB buffer; ~1.5 effective cores of compute to split). Workers are one-shot (no persistent pool) and inputs are cloned whole rather than sliced to band + halo — both are named next optimizations, neither is claimed as done. Only `box-blur` and `gaussian-blur` are band-separable; all other Phase 47 filters execute serially (policy fallback via the async entry points; named refusal from the parallel provider used directly). The 65,536-pixel parallel threshold is a heuristic constant that limits overhead exposure, not a measured optimum — on this hardware serial wins at every measured size. The HTTP routes and the generated C# desktop app do not expose the provider/async API yet. Full detail in `PHASE_51_PROGRESS.md`.

## Acceptance

Phase 51 is ready for the owner's acceptance decision. Implemented and verified: the compute-provider architecture with an honest capability report (GPU asserted unavailable in this runtime), a genuine worker_threads parallel CPU provider for compositing and the separable blurs with byte-identical output, a tested execution policy with recorded fallback reasons, and real benchmarks on two canvas sizes. Stated as not done, with reasons: GPU execution itself (no GPU/WebGPU exists here to implement or verify against), a persistent worker pool, and band-sliced input transfers.
